# 📐 MongoDB Collection Schema Design

> This document defines all MongoDB collections, their fields, data types, validations, and relationships using Mongoose-style schema notation.

---

## 1. 🔐 `users` Collection

Handles authentication and role management.

```js
{
  _id:       ObjectId,              // Auto-generated by MongoDB
  email:     String,   REQUIRED, UNIQUE
  password:  String,   REQUIRED     // bcrypt hashed
  role:      String,   ENUM: ["Admin", "Student"], DEFAULT: "Student"
  createdAt: Date,     DEFAULT: Date.now
}
```

**Notes:**
- `_id` serves as the primary identifier (replaces SQL `user_id`)
- `password` must always be hashed before storing

---

## 2. 🎓 `students` Collection

Stores academic and professional profile of students.

```js
{
  _id:         ObjectId,           // Auto-generated
  userId:      ObjectId, REQUIRED  // ref → users._id (one-to-one)
  name:        String,   REQUIRED
  dept:        String,   REQUIRED  // e.g., "CSE", "ECE", "MECH"
  cgpa:        Number,   REQUIRED  // Range: 0.0 – 10.0
  backlogs:    Number,   DEFAULT: 0
  skills:      [String],           // Array of skill strings e.g. ["Python","SQL"]
  resumePath:  String,             // Relative/absolute file path or URL
  createdAt:   Date,     DEFAULT: Date.now
}
```

**Notes:**
- `userId` links to `users` collection (1-to-1 relationship)
- `skills` stored as an array — more flexible than comma-separated strings
- `cgpa` and `backlogs` are the primary eligibility-check fields

---

## 3. 🏢 `companies` Collection

Stores company listings and their hiring criteria.

```js
{
  _id:                ObjectId,    // Auto-generated
  companyName:        String,   REQUIRED
  jobRole:            String,   REQUIRED  // e.g., "Software Engineer"
  salaryPackage:      Number,   REQUIRED  // In LPA (Lakhs Per Annum)
  minCgpaRequired:    Number,   REQUIRED  // Eligibility: student CGPA must be >= this
  maxBacklogsAllowed: Number,   REQUIRED  // Eligibility: student backlogs must be <= this
  createdAt:          Date,     DEFAULT: Date.now
}
```

**Notes:**
- `minCgpaRequired` and `maxBacklogsAllowed` are used by the **Eligibility Engine**
- Admin manages this collection

---

## 4. 📋 `applications` Collection

Tracks the state of each student's application to a company.

```js
{
  _id:         ObjectId,           // Auto-generated
  studentId:   ObjectId, REQUIRED  // ref → students._id
  companyId:   ObjectId, REQUIRED  // ref → companies._id
  status:      String,   REQUIRED  // ENUM below
                                   // "Applied" | "Shortlisted" | "Technical" | "HR" | "Selected" | "Rejected"
                                   // DEFAULT: "Applied"
  appliedAt:   Date,     DEFAULT: Date.now
  updatedAt:   Date,     DEFAULT: Date.now
}
```

**Status Lifecycle:**
```
Applied → Shortlisted → Technical → HR → Selected
                                       ↘ Rejected (at any stage)
```

**Notes:**
- A student cannot apply twice to the same company (enforced via unique index on `[studentId, companyId]`)
- Admin updates `status`; Student can only view

---

## 5. 📚 `training_sessions` Collection

Stores placement training session records.

```js
{
  _id:         ObjectId,           // Auto-generated
  category:    String,   REQUIRED  // e.g., "Aptitude", "Coding", "HR", "GD"
  sessionDate: Date,     REQUIRED
  trainerName: String,   REQUIRED
  createdAt:   Date,     DEFAULT: Date.now
}
```

**Notes:**
- Both Admin and Students can view sessions
- Only Admin can create/edit/delete sessions

## 🔗 Collection Relationships Summary

| Relationship                  | Type      | Via Field               |
|-------------------------------|-----------|-------------------------|
| users → students              | One-to-One| `students.userId`       |
| students → applications       | One-to-Many | `applications.studentId` |
| companies → applications      | One-to-Many | `applications.companyId` |
| training_sessions             | Standalone | (no FK, viewed by all)  |

---

## 📌 Mongoose Index Recommendations

```js
// Prevent duplicate applications
applications.createIndex({ studentId: 1, companyId: 1 }, { unique: true })

// Fast eligibility filter on companies
companies.createIndex({ minCgpaRequired: 1, maxBacklogsAllowed: 1 })

// User login lookup
users.createIndex({ email: 1 }, { unique: true })
```
